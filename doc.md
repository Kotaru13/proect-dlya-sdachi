# Подробная документация (от лица студента)

## 1) О проекте

Я сделал небольшой мини‑проект на Python — **консольный менеджер задач**.  
Он хранит задачи в файле `tasks.json` и позволяет:

- посмотреть список задач;
- добавить задачу;
- отметить задачу выполненной;
- удалить задачу;
- посмотреть простую статистику (сколько всего / выполнено / осталось).

Запуск:

```bash
python app.py
```

## 2) Зачем нужны форматтер, линтер и pre-commit

На предыдущем этапе проект уже работал и был выложен на GitHub.  
На этом этапе я привёл проект в более аккуратный и поддерживаемый вид:

- **форматтер** — чтобы код был в едином стиле и не было «споров» по пробелам/переносам строк;
- **линтер** — чтобы находить ошибки и плохие практики до запуска программы;
- **pre-commit** — чтобы проверки запускались **автоматически перед коммитом**, и в репозиторий не попадал «грязный» код.

## 3) Какие инструменты я выбрал и почему

Язык проекта — Python, поэтому выбрал стандартную связку:

- **Black** — форматирование кода (быстро и удобно, почти не требует настроек).
- **Ruff** — линтер + автофиксы (работает очень быстро и может исправлять часть проблем сам).
- **pre-commit** — система хуков, которая запускает проверки автоматически перед коммитом.

## 4) Что добавлено в репозиторий

В репозитории появились/изменились файлы:

- `pyproject.toml` — конфигурация для Black и Ruff (линейная длина, версия Python и т.д.).
- `.pre-commit-config.yaml` — список pre-commit хуков (ruff/format + проверки файлов).
- `.gitignore` — добавлено игнорирование `.ruff_cache/`.
- `README.md` — добавлен раздел, как запускать проверки.

## 5) Установка инструментов

Я ставил инструменты через `pip`:

```bash
python -m pip install black ruff pre-commit
```

Проверить, что всё установилось:

```bash
black --version
ruff --version
pre-commit --version
```

## 6) Настройка форматирования и линтера

Настройки лежат в `pyproject.toml`. Я сделал так, чтобы:

- длина строки была 88 (по умолчанию у Black);
- целевая версия Python — 3.10+;
- Ruff проверял базовые категории ошибок (например `E`, `F`) и полезные улучшения.

### Проверить проект вручную

Линтер (без правок):

```bash
ruff check .
```

Форматтер (проверка без изменения файлов):

```bash
black --check .
```

### Автоматически исправить

Ruff может сам исправить часть проблем:

```bash
ruff check . --fix
```

И затем привести всё к стилю Black:

```bash
black .
```

## 7) Настройка pre-commit

Установка хуков в репозиторий:

```bash
pre-commit install
```

Запуск всех хуков на все файлы (полезно перед сдачей):

```bash
pre-commit run --all-files
```

У меня в `.pre-commit-config.yaml` подключены хуки:

- `ruff check` (и автофиксы, где возможно),
- `ruff format`,
- проверки `.yaml`,
- исправление конца файла,
- удаление лишних пробелов в конце строк.

## 8) Как показать, что hooks реально работают

Чтобы продемонстрировать работу `pre-commit`, я делаю так:

1. Нарочно добавляю ошибку, например лишние пробелы в конце строки в каком‑нибудь файле или нарушаю форматирование.
2. Пытаюсь сделать коммит:

```bash
git add .
git commit -m "Проверка pre-commit"
```

3. `pre-commit` останавливает коммит, если находит проблему, и показывает, какая проверка не прошла.
4. После этого я исправляю ошибки (или запускаю автофиксы), снова делаю `git add .` и повторяю `git commit`.

В итоге в `main` попадает только код, который проходит форматирование и линтер.

## 9) Итог по этапу

В результате проект:

- приведён к единому стилю;
- проходит линтер;
- автоматически проверяется перед каждым коммитом через pre-commit.
